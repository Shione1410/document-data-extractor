# 内部構成

## 基本フロー

```text
入力
 ├─ Excel / CSV / Word
 │    └─ 直接抽出
 │
 └─ PDF
      ├─ 文字レイヤーあり → PDF直接抽出
      └─ 文字量が少ない   → PaddleOCR
               ↓
          座標・信頼度取得
               ↓
          読み順の再構成
               ↓
       近接文字列 Smart Merge
               ↓
        ハイフン等の正規化
               ↓
         確認・修正・分類
               ↓
          キーワード整列
               ↓
         Excel / CSV 出力
```

## PDF直接抽出

PyMuPDFを使用します。

PDFから文字ボックスを取得し、座標情報を保持します。

表が検出できる場合はテーブルセル情報も取得します。

## OCR

PaddleOCRを必要時のみ遅延読み込みします。

このため、Excelや文字PDFだけを扱う場合は重いOCRライブラリを起動直後に読み込みません。

OCRパイプライン設定は `OCR.yaml` を明示的に読み込みます。通常実行時とPyInstallerによるexe実行時の両方で、同じ設定を参照できるようにしています。

### 高速

- PP-OCRv5 Mobile
- 220 dpi
- 補正OFF

### 標準

- PP-OCRv6 Small
- 260 dpi
- 補正OFF

### 詳細解析

- PP-OCRv6 Medium
- 300 dpi
- 向き・歪み・文字行補正ON

## 読み順

OCRエンジンの返却順をそのまま採用せず、文字ボックスの高さと縦方向の重なりを用いて行をクラスタリングします。

その後、同一行内を左から右へ並べます。

## Smart Merge

文字列断片間の距離だけでなく、前後の文字種を考慮します。

例:

- 日本語 + 日本語 → 結合寄り
- 英数字 + ハイフン + 英数字 → 結合寄り
- 数字 + 単位 → 結合寄り
- 日本語見出し + 純数字 → 分離寄り

## 分類

分類候補:

- 未判定
- Key
- Value
- 文字列
- 記号
- 不要

手動判定を教師例として、残りのデータを類似度ベースで半自動分類します。

## GUIスレッド

分類処理はバックグラウンドワーカーで行います。

計算終了後にワーカースレッドを終了し、その後GUIへ分割反映します。

これにより大量データ反映時のフリーズを抑えます。

## 出力

ExcelではOCR文字列が `=SUM(...)` 等で始まっても数式として扱われないよう文字列として保存します。

不正なXML制御文字も除去します。

Excel出力には品質情報シートを追加します。

## 業務システム連携の位置づけ

本ツールは、最終的な業務判断を行うアプリではなく、既存文書を業務システムで利用可能なデータへ変換する前処理層として位置づけています。

```text
既存文書
  ↓
Document Data Extractor
  ↓
Bronze / Silver Candidate
  ↓
人手確認
  ↓
Verified master data
  ↓
検索 / 照合 / 要件判定 / 集計等の業務アプリ
```

規格・仕様・要件書では、例外条件や参照関係が重要になるため、抽出した文字列だけで適合判定を自動確定する設計にはしていません。

## exe化

PyInstallerでは `DocumentDataExtractor.spec` を使用します。

- Paddle本体は実行に必要なネイティブバイナリを中心に収集
- PaddleXのデータファイルを収集
- PaddleXが依存確認に使うdistribution metadataを収集
- `OCR.yaml` を同梱

Paddle全体を `collect_all` するとWindows上で不要なC++ヘッダまで収集され、非常に深いパスが生成されるため避けています。
